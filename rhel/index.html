このページについて

Red Hat Enterprise Linux 9.8 の構築・運用で使うコマンドを、利用シーン別に整理したリファレンスです。右上の「コピー」ボタンでクリップボードに取得できます。

'<...>' 部分と、例として記載したホスト名・IPアドレス・パスは環境に合わせて置き換えてください。

対象バージョン：Red Hat Enterprise Linux 9.8 ／ 最終更新：2026年11月

root… root権限（sudo）が必要 pkg… 追加パッケージ・前提製品が必要な場合あり 注意… サービス影響・設定変更あり
該当するコマンドが見つかりませんでした。

01構築時のコマンド

OSインストール直後から運用開始までの初期設定で使うコマンドです。

1-1. 基本設定(ホスト名・時刻・ロケール)

ホスト名を設定(静的ホスト名)
root
hostnamectl set-hostname web01.example.com
タイムゾーンを日本時間に設定
root
timedatectl set-timezone Asia/Tokyo
NTPによる時刻同期を有効化
root
timedatectl set-ntp true
日本語ロケールパッケージを導入
root
dnf install -y glibc-langpack-ja
システムロケールを日本語に設定
root
localectl set-locale LANG=ja_JP.UTF-8
コンソールのキーボード配列を日本語106に設定
root
localectl set-keymap jp106

1-2. サブスクリプション・リポジトリ

アクティベーションキーでシステムを登録
root
subscription-manager register --org=<ORG_ID> --activationkey=<KEY>
登録とRed Hat Insights接続を一括で実施
root
rhc connect --organization <ORG_ID> --activation-key <KEY>
マイナーリリースを9.8に固定(意図しない9.x更新を防止)
root注意
subscription-manager release --set=9.8
有効なリポジトリを確認
root
subscription-manager repos --list-enabled
追加リポジトリを有効化(例:CRB)
root
subscription-manager repos --enable=codeready-builder-for-rhel-9-x86_64-rpms
利用可能なリポジトリ一覧
dnf repolist
全パッケージを最新化
root注意
dnf update -y
パッケージを導入
root
dnf install -y <package>
パッケージグループを一括導入
root
dnf group install -y "Server"

1-3. ネットワーク(NetworkManager)

接続プロファイル一覧(RHEL 9 は keyfile 形式が標準)
nmcli connection show
固定IP・GW・DNSを設定
root
nmcli con mod ens3 ipv4.method manual ipv4.addresses 192.168.10.11/24 ipv4.gateway 192.168.10.1 ipv4.dns "192.168.10.53"
起動時の自動接続を有効化
root
nmcli con mod ens3 connection.autoconnect yes
設定を反映(接続の再有効化)
root注意
nmcli con up ens3
ボンディングI/Fを作成
root
nmcli con add type bond con-name bond0 ifname bond0 bond.options "mode=active-backup,miimon=100"
ボンドにポートを追加
root
nmcli con add type ethernet con-name bond0-p1 ifname ens4 master bond0
VLAN I/Fを作成
root
nmcli con add type vlan con-name vlan100 dev ens3 id 100
TUIでネットワーク設定
root
nmtui

1-4. ストレージ(パーティション・LVM・ファイルシステム)

ディスク・パーティション構成を確認
lsblk
GPTでパーティション作成しLVMフラグ設定
root注意
parted -s /dev/sdb mklabel gpt mkpart primary 0% 100% set 1 lvm on
物理ボリューム(PV)を作成
root
pvcreate /dev/sdb1
ボリュームグループ(VG)を作成
root
vgcreate vgdata /dev/sdb1
論理ボリューム(LV)をVGの空き全量で作成
root
lvcreate -n lvdata -l 100%FREE vgdata
XFSでフォーマット
root注意
mkfs.xfs /dev/vgdata/lvdata
UUIDを確認(fstab記載用)
blkid /dev/vgdata/lvdata
fstabに永続マウントを追記
root注意
echo "UUID=<UUID> /data xfs defaults 0 0" >> /etc/fstab
fstabの記述を検証(再起動前に必ず実施)
root
findmnt --verify
fstabの内容でマウント
root
mount -a
LVを拡張しファイルシステムも同時拡張
root
lvextend -r -L +10G /dev/vgdata/lvdata
スワップ領域を作成・有効化
root
mkswap /dev/vgdata/lvswap && swapon /dev/vgdata/lvswap

1-5. ユーザー・権限

ユーザー作成(wheelグループ付与でsudo可)
root
useradd -m -G wheel opsuser
パスワード設定
root
passwd opsuser
パスワード有効期限90日・14日前警告
root
chage -M 90 -W 14 opsuser
sudo権限を個別ファイルで安全に定義
root
visudo -f /etc/sudoers.d/ops
SSH鍵ペア作成
ssh-keygen -t ed25519
公開鍵を配布
ssh-copy-id opsuser@web01

1-6. サービス管理(systemd)

自動起動を有効化し即時起動
root
systemctl enable --now httpd
自動起動を無効化し停止
root
systemctl disable --now <service>
サービスを起動不可にする
root
systemctl mask <service>
既定ターゲットをCUIに設定
root
systemctl set-default multi-user.target
ユニットファイル変更を反映
root
systemctl daemon-reload

1-7. セキュリティ(firewalld・SELinux・暗号ポリシー)

サービス単位で許可(永続)
root
firewall-cmd --permanent --add-service=https
ポート単位で許可(永続)
root
firewall-cmd --permanent --add-port=8080/tcp
送信元を限定して許可
root
firewall-cmd --permanent --zone=public --add-rich-rule='rule family="ipv4" source address="10.0.0.0/8" service name="ssh" accept'
永続設定をランタイムへ反映
root
firewall-cmd --reload
SELinuxモード確認(Enforcing推奨)
getenforce
独自ディレクトリにSELinuxラベルを定義
rootpkg: policycoreutils-python-utils
semanage fcontext -a -t httpd_sys_content_t "/web(/.*)?"
定義したラベルを適用
root
restorecon -Rv /web
非標準ポートをSELinuxに許可
rootpkg: policycoreutils-python-utils
semanage port -a -t http_port_t -p tcp 8080
SELinuxブール値を永続変更
root
setsebool -P httpd_can_network_connect on
システム全体の暗号ポリシーを設定(DEFAULT/FUTURE/FIPS等)
root注意
update-crypto-policies --set DEFAULT
sshd_config の構文チェック(再起動前に実施)
root
sshd -t

1-8. 時刻同期(chrony)

参照NTPサーバー(server/pool行)を設定
root
vi /etc/chrony.conf
chronydを起動
root
systemctl enable --now chronyd
同期先と同期状態を確認(*が同期中)
chronyc sources -v
時刻を即時補正
root注意
chronyc makestep

1-9. カーネル・チューニング・kdump

用途に応じたtunedプロファイルを適用
root
tuned-adm profile throughput-performance
カーネルパラメータを永続設定
root
echo "vm.swappiness = 10" > /etc/sysctl.d/90-custom.conf
sysctl設定を全て再読込
root
sysctl --system
カーネル起動パラメータを追加
root注意
grubby --update-kernel=ALL --args="<param>"
crashkernel予約値を推奨値に設定(要再起動)
root
kdumpctl reset-crashkernel --kernel=ALL
kdumpを有効化
root
systemctl enable --now kdump
journalを永続化(前回起動時ログの保全用)
root
mkdir -p /var/log/journal && systemctl restart systemd-journald
Web管理コンソール(Cockpit, 9090/tcp)を有効化
root
systemctl enable --now cockpit.socket

04障害時の調査

初動(状況把握)→ログ確認→リソース確認→個別調査の順に実施します。証跡保全のため、調査前に sos report を取得しておくことを推奨します。

4-1. 初動・状況把握

起動失敗しているユニット

稼働時間・再起動/シャットダウン履歴

4-2. ログ確認(journald / rsyslog)

今回起動以降のエラー以上のログ

起動履歴一覧
journalctl --list-boots
前回起動時のログ末尾(突然の再起動調査、要永続化)
journalctl -b -1 -e
カーネルメッセージ
journalctl -k
リアルタイム追跡
journalctl -f
カーネルリングバッファ(時刻表示)
root
dmesg -T --level=err,warn
システムログ
root
less /var/log/messages
認証・sudoログ
root

4-3. リソース枯渇

コアダンプの詳細(バックトレース)
root

4-5. ネットワーク

IP・経路の確認

通信遮断の原因確認

09知っておくと便利なコマンド 追加

作業ログの記録、変更を安全に戻せるようにする仕組み、サーバー間の差分チェックなど、知っていると作業効率と品質が大きく変わるコマンドです。

9-1. 作業を効率よく・記録を残す

ターミナル操作をまるごと記録（作業エビデンス）
bash
exit するまでの入力と出力がすべてファイルに残ります。作業前に実行しておくと、手順書との突き合わせや障害時の振り返りに使えます。
script -a /var/tmp/work_$(hostname -s)_$(date +%Y%m%d_%H%M).log
# ... 作業 ...
exit
SSH が切れても作業を継続（tmux）
pkg: tmux
長時間かかる処理（dnf update・バックアップなど）は tmux の中で実行すると、回線断でも止まりません。
tmux new -s work        # セッション開始
# Ctrl+b → d でデタッチ（処理は継続）
tmux ls                 # セッション一覧
tmux attach -t work     # 再接続
コマンド履歴に実行日時を残す
root
全ユーザーの history に日時が付きます。誰がいつ何を実行したかの調査に役立ちます。
echo 'export HISTTIMEFORMAT="%F %T "' > /etc/profile.d/histtime.sh
echo 'export HISTSIZE=10000' >> /etc/profile.d/histtime.sh
history | tail -20      # 再ログイン後に確認
変化をハイライトしながら定期実行
-d で前回との差分が強調表示されます。切替試験や負荷試験の監視に便利です。
watch -n 2 -d 'ss -s; free -h'
watch -n 5 -d 'systemctl is-active httpd chronyd sshd'
応答しないコマンドに制限時間を付ける
NFS のハングや名前解決待ちで、スクリプト全体が止まるのを防ぎます。
timeout 10 df -h          # 10秒で打ち切り（終了コード 124）
timeout 5 getent hosts db01.example.com || echo "名前解決NG"
踏み台経由で一発ログイン
~/.ssh/config に書いておくと、scp・rsync も踏み台経由で使えます。
ssh -J bastion.example.com web01.example.com

# ~/.ssh/config
Host web*
  ProxyJump bastion.example.com
  User opsuser

9-2. サーバー間の差分チェック・標準化

2台のサーバーのパッケージ差分

     <(ssh web02 "rpm -qa --qf '%{NAME}-%{VERSION}-%{RELEASE}\n' | sort")
設定ファイル・パラメータの差分

結果の先頭にホスト名を付けて一覧にします。

Ansible でドライラン（変更せずに差分だけ確認）

--check --diff で、どのファイルがどう変わるかを適用前に確認できます。RHEL のシステムロール（timesync・selinux・firewall など）を使うと標準設定をコード化できます。

9-3. 安全に変更する・戻せるようにする

systemd の設定はドロップインで上書き

root

Aエビデンス一括取得スクリプト

「2. 構築完了後の構成情報の取得」の主要コマンドをまとめて実行し、結果をホスト単位で tar.gz に保存するスクリプト例です。構築完了時と変更作業の前後で取得し、diff で比較すると差分確認(テスト自動化)に利用できます。

一括取得スクリプト（例）
bash
#!/bin/bash
# RHEL 9 構成情報エビデンス一括取得スクリプト(root で実行)
OUT=/var/tmp/evidence_$(hostname -s)_$(date +%Y%m%d_%H%M%S)
mkdir -p "$OUT"
run() { echo "### $2" > "$OUT/$1.txt"; eval "$2" >> "$OUT/$1.txt" 2>&1; }
run os        "cat /etc/redhat-release; uname -a; hostnamectl"
run cpu_mem   "lscpu; free -h; lsmem"
run hw        "dmidecode -t system"
run storage   "lsblk -f; df -hT; findmnt; cat /etc/fstab; pvs; vgs; lvs"
run network   "ip -br addr; ip route; nmcli dev status; cat /etc/resolv.conf /etc/hosts; ss -tulnp"
run packages  "rpm -qa --qf '%{NAME}-%{VERSION}-%{RELEASE}.%{ARCH}\n' | sort"
run services  "systemctl list-unit-files --type=service --state=enabled; systemctl list-timers --all"
run security  "firewall-cmd --list-all-zones; sestatus; update-crypto-policies --show; sshd -T"
run users     "getent passwd; getent group; ls -l /etc/sudoers.d"
run kernel    "cat /proc/cmdline; tuned-adm active; sysctl -a"
run time      "timedatectl; chronyc sources; localectl"
tar czf "$OUT.tar.gz" -C "$(dirname "$OUT")" "$(basename "$OUT")"
echo "出力: $OUT.tar.gz"

B利用上の注意

  • IPアドレス・I/F名(ens3 等)・<> で囲んだ値は、環境に合わせて置き換えてください。
  • 「注意」が付いたコマンドは、サービス停止・業務影響・データ変更を伴う可能性があります。本番環境では事前に検証環境で確認し、作業手順書に基づいて実施してください。
  • 「pkg」が付いたコマンドは、最小インストール構成では未導入の場合があります。dnf install で導入してください。
  • RHEL 9 ではネットワーク設定は NetworkManager(keyfile 形式)が標準で、旧 network-scripts は廃止されています。abrt に代わり systemd-coredump(coredumpctl)を利用します。
  • 前回起動時のログ(journalctl -b -1)を参照するには journal の永続化が必要です。

掲載コマンドは一般的な仕様に基づくサンプルです。バージョンやエディションにより利用できない構文があります。本番環境で実行する前に、検証環境とRed Hatの公式マニュアルで確認してください。
