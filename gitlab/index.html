このページについて

GitLab Self-Managed(Linuxパッケージ版)on RHEL 9 の構築・運用で使うコマンドを、利用シーン別に整理したリファレンスです。右上の「コピー」ボタンでクリップボードに取得できます。

'<...>' 部分と、例として記載したホスト名・IPアドレス・パスは環境に合わせて置き換えてください。

対象バージョン：GitLab Self-Managed(Linuxパッケージ版)on RHEL 9 ／ 最終更新：2026年11月

root… root権限（sudo）が必要 pkg… 追加パッケージ・前提製品が必要な場合あり 注意… サービス影響・設定変更あり
該当するコマンドが見つかりませんでした。

01構築時のコマンド

Linuxパッケージ(Omnibus)版を RHEL 9 にインストールする場合のコマンドです。設定はすべて /etc/gitlab/gitlab.rb に集約し、gitlab-ctl reconfigure で反映します。

1-1. 事前準備

依存パッケージを導入
root
dnf install -y curl policycoreutils perl openssh-server
SSH(Git over SSH用)を有効化
root
systemctl enable --now sshd
HTTP/HTTPSを許可
root
firewall-cmd --permanent --add-service={http,https} && firewall-cmd --reload

1-2. インストール

GitLab公式リポジトリを登録(CE版は gitlab-ce)
root
curl -sS https://packages.gitlab.com/install/repositories/gitlab/gitlab-ee/script.rpm.sh | bash
外部URLを指定してインストール
root
EXTERNAL_URL="https://gitlab.example.com" dnf install -y gitlab-ee
バージョンを指定してインストール(標準化・再現性のため推奨)
root
dnf install -y gitlab-ee-<バージョン>
rootユーザーの初期パスワード(24時間後に自動削除)
root
cat /etc/gitlab/initial_root_password

1-3. 設定・反映

主設定ファイル(external_url、SMTP、バックアップ先、LDAP等)
root
vi /etc/gitlab/gitlab.rb
gitlab.rb の内容を反映
root注意
gitlab-ctl reconfigure
gitlab.rb と最新テンプレートの差分を確認(アップグレード後)
root
gitlab-ctl diff-config
将来廃止される設定の有無をチェック
root
gitlab-ctl check-config
構築後の総合チェック
root
gitlab-rake gitlab:check SANITIZE=true

1-4. GitLab Runner

Runnerを導入(Runnerリポジトリ登録後)
root
dnf install -y gitlab-runner
RunnerをGitLabに登録
root
gitlab-runner register --url https://gitlab.example.com --token <Runner認証トークン>
登録済みRunnerの接続確認
root
gitlab-runner verify

02構築完了後の構成情報の取得

バージョン・コンポーネント構成・設定値を取得します。gitlab.rb と gitlab-secrets.json は構成管理上もっとも重要なファイルです。

2-1. バージョン・環境

GitLab・Ruby・DB・Gitalyなどのバージョンと環境情報
root
gitlab-rake gitlab:env:info
インストールパッケージのバージョン
head -1 /opt/gitlab/version-manifest.txt
ライセンス情報(EE)
root
gitlab-rake gitlab:license:info
有効なサービス(コンポーネント)一覧
root
gitlab-ctl service-list

2-2. 設定

gitlab.rb の有効な設定行のみ表示
root
grep -vE '^\s*(#|$)' /etc/gitlab/gitlab.rb
反映される設定値(JSON)を出力
root
gitlab-ctl show-config
設定ファイル・証明書・secretsの配置
root
ls -l /etc/gitlab/

2-3. データ・Runner

コンポーネント別のデータ容量(git-data、postgresql等)
root
du -sh /var/opt/gitlab/*
登録済みRunner一覧
root
gitlab-runner list
Runnerのバージョン
gitlab-runner --version

03性能情報の取得

Puma(Web)、Sidekiq(バックグラウンド処理)、Gitaly(Git)、PostgreSQL の各コンポーネントの状態と、OSリソースを確認します。

3-1. コンポーネントの状態

各サービスの稼働状態と稼働時間
root
gitlab-ctl status
各コンポーネントの準備状態(監視用エンドポイント、許可IPから実行)
curl -s http://127.0.0.1/-/readiness?all=1
生存確認エンドポイント
curl -s http://127.0.0.1/-/liveness
Sidekiqキューの滞留件数
root
gitlab-rails runner 'Sidekiq::Queue.all.each { |q| puts "#{q.name}: #{q.size}" }'

3-2. データベース

PostgreSQLの接続数
root
gitlab-psql -c "SELECT count(*) FROM pg_stat_activity;"
DBサイズ
root
gitlab-psql -c "SELECT pg_size_pretty(pg_database_size('gitlabhq_production'));"
マイグレーション状態(down が残っていないか)
root
gitlab-rake db:migrate:status

3-3. OSリソース

メモリ使用量上位(puma・sidekiq・postgres)
top -b -n 1 -o %MEM | head -20
コンポーネント別のCPU・メモリ
pkg: sysstat
pidstat -u -r -C "puma|sidekiq|gitaly|postgres" 1 5
/var/opt/gitlab のディスクI/O
pkg: sysstat
iostat -xz 1 5

04障害時の調査

ログはコンポーネントごとに /var/log/gitlab/ 配下に出力されます。gitlab-ctl tail でリアルタイムに確認しながら切り分けます。

4-1. 状態確認・チェック

停止(down)しているサービスの特定
root
gitlab-ctl status
構成チェック(Gitaly・Sidekiq・権限など)
root
gitlab-rake gitlab:check SANITIZE=true
DB内の暗号化値が現在のsecretsで復号できるか確認
root
gitlab-rake gitlab:doctor:secrets
外部サービス(LDAP・SMTP等)へのTCP疎通
root
gitlab-rake gitlab:tcp_check[<ホスト>,<ポート>]

4-2. ログ確認

全コンポーネントのログをリアルタイム表示
root
gitlab-ctl tail
特定コンポーネント(puma/sidekiq/gitaly/nginx/postgresql)のログ
root
gitlab-ctl tail puma
Railsのリクエストログ(JSON)
root
less /var/log/gitlab/gitlab-rails/production_json.log
アプリケーション例外ログ
root
less /var/log/gitlab/gitlab-rails/exceptions_json.log
バックグラウンドジョブのログ
root
less /var/log/gitlab/sidekiq/current
Nginxエラーログ(502等の調査)
root
less /var/log/gitlab/nginx/gitlab_error.log

4-3. 復旧操作

全サービス再起動
root注意
gitlab-ctl restart
特定サービスのみ再起動
root注意
gitlab-ctl restart sidekiq
Pumaを処理中リクエスト完了後に再起動
root
gitlab-ctl hup puma
Redisキャッシュをクリア(表示不整合時)
root注意
gitlab-rake cache:clear
rootパスワードの再設定
root注意
gitlab-rake "gitlab:password:reset[root]"

4-4. 詳細調査

Railsコンソール(データの直接参照・操作。誤操作に注意)
root注意
gitlab-rails console
PostgreSQLへ接続
root注意
gitlab-psql
Redisへ接続
root

メンテナンス画面を表示(調査中の利用停止)
root注意

05バックアップ・リストア

アプリケーションデータは gitlab-backup、設定ファイルは gitlab-ctl backup-etc で取得します。gitlab-secrets.json はアプリケーションバックアップに含まれないため、必ず別途保管してください。

5-1. バックアップ

アプリケーションデータ(DB・リポジトリ・アップロード等)のバックアップ
root
gitlab-backup create STRATEGY=copy
/etc/gitlab(gitlab.rb・gitlab-secrets.json)のバックアップ
root
gitlab-ctl backup-etc
バックアップファイルの確認
root
ls -lh /var/opt/gitlab/backups/

5-2. リストア

リストア前にDB接続プロセスを停止
root注意
gitlab-ctl stop puma && gitlab-ctl stop sidekiq
バックアップからリストア(同一バージョンが前提)
root注意
gitlab-backup restore BACKUP=<タイムスタンプ>
リストア後の再構成・再起動
root注意
gitlab-ctl reconfigure && gitlab-ctl restart

06アップグレード

アップグレードはサポートされたアップグレードパスに沿って段階的に実施します。各段階で、バックグラウンドマイグレーションの完了(管理エリア > Monitoring > Background migrations)を確認してから次へ進みます。

6-1. 手順

事前バックアップ
root
gitlab-backup create STRATEGY=copy && gitlab-ctl backup-etc
指定バージョンへアップグレード(reconfigureは自動実行)
root注意
dnf install -y gitlab-ee-<次のバージョン>
マイグレーション完了確認
root
gitlab-rake db:migrate:status
アップグレード後のチェック
root
gitlab-rake gitlab:check SANITIZE=true
新バージョンの設定テンプレートとの差分
root
gitlab-ctl diff-config

07知っておくと便利なコマンド 追加

JSON ログの絞り込み、API や CLI による操作の自動化、データ整合性のチェックなど、知っていると運用の効率と品質が上がるコマンドです。

7-1. ログを素早く絞り込む

JSON ログを jq で絞り込み（エラーだけ・遅いリクエストだけ）
rootpkg: jq
GitLab のログは JSON 形式なので、jq で条件を指定して抽出できます。
# 500 系エラーのリクエスト
jq -c 'select(.status >= 500) | {time, method, path, status, duration_s}' \
  /var/log/gitlab/gitlab-rails/production_json.log | tail -20

# 5秒以上かかったリクエスト
jq -c 'select(.duration_s > 5) | {time, path, duration_s, user_id}' \
  /var/log/gitlab/gitlab-rails/production_json.log | tail -20
相関 ID で1件のリクエストを全ログから追跡
root
エラー画面やログに出る correlation_id で、Rails・Sidekiq・Gitaly のログを横断して検索できます。
grep -r "<correlation_id>" /var/log/gitlab/ | less
失敗した Sidekiq ジョブの集計
rootpkg: jq
jq -r 'select(.job_status == "fail") | .class' /var/log/gitlab/sidekiq/current | sort | uniq -c | sort -rn | head

7-2. API・CLI で自動化する

REST API でプロジェクト一覧を取得
アクセストークン（read_api 権限）で利用できます。棚卸しや定期レポートに便利です。
curl -s --header "PRIVATE-TOKEN: <アクセストークン>" \
  "https://gitlab.example.com/api/v4/projects?per_page=100&simple=true" \
  | jq -r '.[] | [.id, .path_with_namespace, .last_activity_at] | @tsv'
バージョンを API で確認（外部から）
curl -s --header "PRIVATE-TOKEN: <アクセストークン>" https://gitlab.example.com/api/v4/version
glab CLI で MR・パイプラインを操作
pkg: glab
GitLab 公式の CLI です。ブラウザを開かずに MR やパイプラインの状況を確認できます。
glab auth login --hostname gitlab.example.com
glab mr list
glab ci status
glab ci lint                      # .gitlab-ci.yml の構文チェック
glab api projects/:id/pipelines   # 任意の API を呼び出し
Rails ランナーで管理者ユーザーを棚卸し
root
gitlab-rails runner 'User.admins.each { |u| puts [u.username, u.email, u.last_sign_in_at].join("\t") }'

7-3. データ整合性のチェック

添付ファイル・CI 成果物・LFS の整合性確認
root
バックアップのリストア後や、ストレージ移行後に実行します。
gitlab-rake gitlab:uploads:check
gitlab-rake gitlab:artifacts:check
gitlab-rake gitlab:lfs:check
孤立した CI 成果物ファイルの確認（ドライラン）
root
既定はドライランで、削除せずに対象だけを表示します。
gitlab-rake gitlab:cleanup:orphan_job_artifact_files
# 実際に削除する場合（注意）
# gitlab-rake gitlab:cleanup:orphan_job_artifact_files DRY_RUN=false
コンテナレジストリの不要データを削除
root注意
削除中はレジストリが読み取り専用になります。メンテナンス時間に実行してください。
gitlab-ctl registry-garbage-collect -m

7-4. 運用の小技

データベースへ直接接続（参照のみ）
root注意
更新は行わず、調査目的の参照にとどめてください。
gitlab-rails dbconsole --database main
# 例: SELECT count(*) FROM users WHERE state = 'active';
ロックされたユーザーの解除
root注意
ログイン失敗の繰り返しでロックされたユーザーを解除します。
gitlab-rails runner 'User.find_by_username("<ユーザー名>").unlock_access!'
Runner をデバッグモードで起動
root
ジョブが取得されない・失敗する原因をログで詳しく確認できます。
gitlab-runner stop
gitlab-runner --debug run
GitLab のバージョンをすばやく確認
gitlab-rails runner "puts Gitlab::VERSION"

A構成情報一括取得スクリプト

バージョン・設定・コンポーネント状態を取得して保存するスクリプト例です。gitlab-secrets.json などの秘密情報は出力に含めていません。秘密情報は別途、安全な場所に保管してください。

一括取得スクリプト（例）
bash
#!/bin/bash
# GitLab 構成情報一括取得スクリプト(root で実行)
OUT=/var/tmp/gitlab_evidence_$(hostname -s)_$(date +%Y%m%d_%H%M%S)
mkdir -p "$OUT"
run() { echo "### $2" > "$OUT/$1.txt"; eval "$2" >> "$OUT/$1.txt" 2>&1; }
run version   "head -1 /opt/gitlab/version-manifest.txt"
run env_info  "gitlab-rake gitlab:env:info"
run status    "gitlab-ctl status"
run services  "gitlab-ctl service-list"
run config    "grep -vE '^\s*(#|$)' /etc/gitlab/gitlab.rb | grep -viE 'password|secret|token'"
run check     "gitlab-rake gitlab:check SANITIZE=true"
run migrate   "gitlab-rake db:migrate:status | grep -c down"
run disk      "du -sh /var/opt/gitlab/*"
run runner    "gitlab-runner list"
tar czf "$OUT.tar.gz" -C "$(dirname "$OUT")" "$(basename "$OUT")"
echo "出力: $OUT.tar.gz"

B利用上の注意

  • <> で囲んだ値は、環境に合わせて置き換えてください。URL(gitlab.example.com)は環境に合わせてください。
  • 「注意」が付いたコマンドは、サービス停止・業務影響・データ変更を伴う可能性があります。本番環境では事前に検証環境で確認し、作業手順書に基づいて実施してください。
  • Linuxパッケージ(Omnibus)版が対象です。Docker版・Helmチャート版ではコマンドの実行方法が異なります。
  • gitlab.rb を変更したら gitlab-ctl reconfigure で反映します。/var/opt/gitlab 配下の設定ファイルを直接編集しても、reconfigure で上書きされます。
  • バックアップのリストアは、取得時と同じ GitLab バージョン・エディションが前提です。gitlab-secrets.json がないと、暗号化されたデータ(CI/CD 変数・2FA 等)を復元できません。
  • gitlab-rails console と gitlab-psql はデータを直接操作できるため、本番での更新系操作は手順化してから実施してください。

掲載コマンドは一般的な仕様に基づくサンプルです。バージョンやエディションにより利用できない構文があります。本番環境で実行する前に、検証環境とGitLabの公式マニュアルで確認してください。
