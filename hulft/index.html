01構築時のコマンド

インストール後の環境設定、デーモン起動、管理情報の登録で使うコマンドです。HULFT10 では管理情報を HULFT Management Console(Web)で操作できますが、標準化・自動化にはパラメータファイルを使った一括登録をおすすめします。

1-1. 環境変数・環境設定ファイル

実行モジュール格納ディレクトリを設定
export HULEXEP=/usr/local/HULFT/bin
環境設定ファイル(hulenv.conf 等)格納ディレクトリを設定
export HULPATH=/usr/local/HULFT/etc
HULFTコマンドにパスを通す
export PATH=$HULEXEP:$PATH
システム動作環境設定(ポート番号・トレース出力・文字コード等)を編集
root注意
vi $HULPATH/hulenv.conf
配信/集信(既定30000)・要求受付(既定31000)ポートを許可
root
firewall-cmd --permanent --add-port={30000,31000}/tcp && firewall-cmd --reload

1-2. デーモンの起動・自動起動

配信デーモンを起動
root
hulsndd
集信デーモンを起動
root
hulrcvd
要求受付デーモンを起動
root
hulobsd
起動(start)・停止(stop)用スクリプトを作成(3デーモンを一括操作)
root
vi /usr/local/bin/hulft
自動起動用のsystemdユニットを作成(ExecStart/ExecStop に上記スクリプト)
root
vi /etc/systemd/system/hulft.service
OS起動時の自動起動を有効化
root
systemctl daemon-reload && systemctl enable --now hulft

1-3. 管理情報の登録(パラメータファイル)

詳細ホスト情報を一括登録
root
utliupdt -f /work/hst.prm
配信管理情報を一括登録
root
utliupdt -f /work/snd.prm
集信管理情報を一括登録
root
utliupdt -f /work/rcv.prm
既存IDを置き換えて登録(更新時)
root注意
utliupdt -f /work/snd.prm -r

1-4. 疎通・転送テスト

配信要求(同期転送で結果を確認)
utlsend -f <FILEID> -h <相手ホスト> -sync
集信側から送信要求(同期転送)
utlrecv -f <FILEID> -h <相手ホスト> -sync
直前コマンドの終了コード確認(0=正常)
echo $?

02構築完了後の構成情報の取得

パラメータシート・完成図書の裏付けとして取得します。utligen で出力したパラメータファイルは、そのまま他環境への移行や差分比較に使えます。

2-1. 管理情報

詳細ホスト情報をパラメータファイルに出力
utligen -f /tmp/hst.prm -i hst -id "*"
配信管理情報を出力
utligen -f /tmp/snd.prm -i snd -id "*"
集信管理情報を出力
utligen -f /tmp/rcv.prm -i rcv -id "*"
ジョブ起動情報を出力
utligen -f /tmp/job.prm -i job -id "*"
主要な管理情報を1ファイルに一括出力
utligen -f /tmp/all.prm -i snd -id "*" -i rcv -id "*" -i hst -id "*" -i job -id "*" -i tgrp -id "*"
管理情報の関連(配信→ホスト・ジョブ等)を一覧表示
utlidlist -i snd -id <FILEID> -l

2-2. 環境・プロセス

システム動作環境設定
cat $HULPATH/hulenv.conf
自動起動設定
cat /etc/systemd/system/hulft.service /usr/local/bin/hulft
3デーモンの稼働確認
ps -ef | grep -E "hulsndd|hulrcvd|hulobsd" | grep -v grep
待ち受けポート確認
root
ss -tlnp | grep -E ":(30000|31000)"

転送実績(件数・サイズ・所要時間)と、転送中のリソース使用状況を確認します。

3-1. 転送状況・実績

要求受付履歴(相手からの要求の受付状況)

HULFTプロセスのCPU・メモリ・I/O

04障害時の調査

転送エラーは、履歴の完了コード(詳細コード)をエラーコード表と照合して原因を切り分けます。

4-1. 状態確認

デーモン停止の有無
ps -ef | grep -E "hulsndd|hulrcvd|hulobsd" | grep -v grep
対象転送の完了コード・詳細コード
utllist -s -f <FILEID> -h <HOST>
集信側の完了コード
utllist -r -f <FILEID>
相手からの要求が届いているか確認
utlobslist -h <HOST>
転送が滞留していないか確認
utlsdisp; utlrdisp

4-2. ログ・通信

起動・停止時のメッセージ(systemd経由)
journalctl -u hulft --since today
syslog出力時のHULFTメッセージ(-s 指定で起動した場合)
root
grep -i hul /var/log/messages
トレースログ・制御ファイルの更新状況(出力先は hulenv.conf で確認)
ls -lt $HULPATH
相手の集信ポートへの疎通
pkg: nmap-ncat
nc -vz <相手ホスト> 30000
名前解決(詳細ホスト情報のホスト名と一致するか)
getent hosts <相手ホスト>
HULFT通信のパケットキャプチャ
rootpkg: tcpdump注意
tcpdump -i any -nn port 30000 or port 31000 -w /tmp/hulft.pcap

4-3. 再送・リカバリ

再送要求(中断箇所=チェックポイントから再送)
utlrecv -r -h <送信元ホスト> -f <FILEID>
先頭から再送を要求
注意
utlrecv -r -h <送信元ホスト> -f <FILEID> -np
送信側から再配信
注意
utlsend -f <FILEID> -h <HOST> -sync

4-4. デーモンの再起動

配信・集信・要求受付デーモンを停止
root注意
utlkillsnd; utlkillrcv; utlkillobs
3デーモンを再起動
root
hulsndd; hulrcvd; hulobsd
systemd管理の場合の一括再起動
root注意

05日常運用・メンテナンス

履歴ファイルの肥大化防止や、定期的な管理情報のバックアップに使います。

5-1. 履歴管理

削除前に配信履歴を退避
utllist -s -from <日付> -to <日付> > /backup/sndlog_$(date +%Y%m%d).txt
指定日以前の配信履歴を削除(-r:集信、-a:両方、-i:対話モード)
root注意
utllog -s -to <日付>
前月分の配信・集信履歴を削除
root注意
utllog -a -lastmonth
集信準備完了通知(全ホストへ再送要求を発行、デーモン起動直後等)
utlrecv -a

5-2. バックアップ

環境設定・管理情報ファイルを退避(デーモン停止中に実施)
root
tar czf /backup/hulft_etc_$(date +%F).tar.gz $HULPATH
管理情報をテキスト形式で退避(差分比較・移行用)
utligen -f /backup/hulft_all_$(date +%F).prm -i snd -id "*" -i rcv -id "*" -i hst -id "*" -i job -id "*"

06知っておくと便利なコマンド 追加

転送データの検証、ジョブからの安全な呼び出し、環境間の管理情報の比較など、HULFT のコマンドと OS コマンドを組み合わせて使うと便利な手順です。

6-1. 転送データの検証

送受信ファイルの一致確認（チェックサム）
送信側と受信側で同じ値になれば、内容が一致しています。コード変換なし（バイナリ転送）の場合に使えます。
sha256sum /data/send/SAMPLE.dat        # 送信側
sha256sum /data/recv/SAMPLE.dat        # 受信側
件数（レコード数）とサイズの確認
テキスト転送でコード変換・改行変換がある場合は、チェックサムではなく件数で突き合わせます。
wc -l /data/recv/SAMPLE.dat
ls -l --time-style=full-iso /data/recv/SAMPLE.dat
文字コード・改行コードの確認
文字化けや「1行に連結された」などのトラブル時に確認します。^M（\r）が見えれば CRLF です。
file -i /data/recv/SAMPLE.dat
head -3 /data/recv/SAMPLE.dat | od -c | head
nkf --guess /data/recv/SAMPLE.dat       # nkf 導入時
転送前に、ファイルが書き込み中でないか確認
root
他のプロセスが書き込み中のファイルを送ると、途中までのデータが届きます。
lsof /data/send/SAMPLE.dat || echo "使用中のプロセスなし"
fuser -v /data/send/SAMPLE.dat

6-2. ジョブ・スクリプトからの呼び出し

同期転送の結果で処理を分岐
bash
-sync 指定で転送完了まで待ち、終了コードで成否を判定します。ジョブ管理製品から呼び出すときの基本形です。
utlsend -f SAMPLE01 -h recvhost -sync
rc=$?
if [ $rc -ne 0 ]; then
  echo "$(date '+%F %T') utlsend NG rc=$rc" >> /var/tmp/hulft_job.log
  utllist -s -f SAMPLE01 -h recvhost | tail -5 >> /var/tmp/hulft_job.log
  exit $rc
fi
cron・ジョブから実行するときの環境変数
bash
cron は環境変数を引き継がないため、HULEXEP・HULPATH を明示しないとコマンドが見つからない／設定ファイルを読めない状態になります。
#!/bin/bash
export HULEXEP=/usr/local/HULFT/bin
export HULPATH=/usr/local/HULFT/etc
export PATH=$HULEXEP:$PATH
utlsend -f SAMPLE01 -sync
直近の転送結果だけを確認
utllist -s -f SAMPLE01 | tail -5        # 配信側
utllist -r -f SAMPLE01 | tail -5        # 集信側

6-3. 管理情報の比較・移行

環境間（本番・検証）の管理情報の差分
bash
utligen で出力したパラメータファイルを比較すると、設定漏れや環境差異を確認できます。
ssh prdhost 'utligen -f /tmp/snd_prd.prm -i snd -id "*"' && scp prdhost:/tmp/snd_prd.prm .
ssh stghost 'utligen -f /tmp/snd_stg.prm -i snd -id "*"' && scp stghost:/tmp/snd_stg.prm .
diff -u snd_stg.prm snd_prd.prm
管理情報を Git で構成管理
pkg: git
定期的に utligen の結果をコミットしておくと、いつ・何が変わったかを追跡できます。
cd /opt/hulft-config && for i in hst snd rcv job; do utligen -f mng_$i.prm -i $i -id "*"; done
git add -A && git commit -m "HULFT 管理情報 $(date +%F)"
特定 ID だけを別環境へ移行
注意
-r 付きで登録すると、同じ ID の既存定義を置き換えます。
utligen -f snd_SAMPLE01.prm -i snd -id SAMPLE01     # 移行元
utliupdt -f snd_SAMPLE01.prm -r                     # 移行先

6-4. 通信・運用の小技

転送中の TCP 接続を確認
root
転送が滞留しているときに、相手との接続が張られているかを確認します。
ss -tnp '( sport = :30000 or dport = :30000 )'
相手ホスト名の解決結果を確認
詳細ホスト情報に登録したホスト名が、意図した IP に解決されるか確認します（hosts と DNS の食い違いに注意）。
getent hosts recvhost
grep -i recvhost /etc/hosts
受信ディレクトリの空き容量を事前確認
集信ファイルの書き込み失敗（容量不足）を事前に防ぎます。
df -h /data/recv
du -sh /data/recv

A構成情報一括取得スクリプト

管理情報をパラメータファイル形式で出力し、環境設定ファイルとあわせて保存するスクリプト例です。構築完了時と変更作業の前後で取得し、diff で比較すると管理情報の差分確認に使えます。

一括取得スクリプト（例）
bash
#!/bin/bash
# HULFT10 構成情報一括取得スクリプト(HULFT 実行ユーザーで実行)
export HULEXEP=/usr/local/HULFT/bin HULPATH=/usr/local/HULFT/etc
export PATH=$HULEXEP:$PATH
OUT=/var/tmp/hulft_evidence_$(hostname -s)_$(date +%Y%m%d_%H%M%S)
mkdir -p "$OUT"
for i in hst snd rcv job tgrp fmt mfmt; do
  utligen -f "$OUT/mng_${i}.prm" -i $i -id "*" > "$OUT/mng_${i}.log" 2>&1
done
cp -p "$HULPATH/hulenv.conf" "$OUT/"
ps -ef | grep -E "hulsndd|hulrcvd|hulobsd" | grep -v grep > "$OUT/process.txt"
utllist -s > "$OUT/sndlog.txt" 2>&1
utllist -r > "$OUT/rcvlog.txt" 2>&1
tar czf "$OUT.tar.gz" -C "$(dirname "$OUT")" "$(basename "$OUT")"
echo "出力: $OUT.tar.gz"

B利用上の注意

  • <> で囲んだ値は、環境に合わせて置き換えてください。HULEXEP・HULPATH のパスは導入時の指定に合わせてください。
  • 「注意」が付いたコマンドは、サービス停止・業務影響・データ変更を伴う可能性があります。本番環境では事前に検証環境で確認し、作業手順書に基づいて実施してください。
  • ポート番号(配信・集信 30000、要求受付 31000)は既定値です。hulenv.conf と詳細ホスト情報の設定を確認してください。
  • 管理情報の参照・登録は HULFT Management Console(Web)でも行えます。複数環境への展開や差分管理には、パラメータファイル(utligen/utliupdt)の利用をおすすめします。
  • クラスター構成(Enterprise グレード)では、デーモンの起動・停止に hulclustersnd / hulclusterrcv / hulclusterobs(-start)を使います。
  • 日付の指定形式は、システム動作環境設定の日付フォーマット(datefmt)に従います。

掲載コマンドは一般的な仕様に基づくサンプルです。バージョンやエディションにより利用できない構文があります。本番環境で実行する前に、検証環境とセゾンテクノロジー(HULFT)の公式マニュアルで確認してください。
