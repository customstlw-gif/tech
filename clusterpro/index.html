このページについて

CLUSTERPRO X 6.0 for Linux の構築・運用で使うコマンドを、利用シーン別に整理したリファレンスです。右上の「コピー」ボタンでクリップボードに取得できます。

'<...>' 部分と、例として記載したホスト名・IPアドレス・パスは環境に合わせて置き換えてください。

対象バージョン：CLUSTERPRO X 6.0 for Linux ／ 最終更新：2026年11月

01構築時のコマンド

インストール、ライセンス登録、クラスタ構成情報の適用、初回起動で使うコマンドです。構成の作成は Cluster WebUI(既定 https://<サーバー>:29003)で行い、コマンドは適用・確認・自動化に使います。

1-1. インストール・事前設定

本体をインストール(全ノードで実施)
root
rpm -ivh clusterpro-<バージョン>.x86_64.rpm
CLUSTERPROが使うポートをfirewalldに一括登録(X 4.3以降)
root
clpfwctrl.sh --add
全ノードの名前解決を設定(ハートビート経路含む)
root
vi /etc/hosts
ノード間の時刻同期を確認(ノード間のログ突合せのため)
chronyc sources

1-2. ライセンス

ライセンスを登録
root
clplcnsc -i <ライセンスファイル>
登録済みライセンスを一覧表示
root
clplcnsc -l -a

1-3. 構成情報の適用・バックアップ

Cluster WebUIで作成した構成情報(clp.conf)を全ノードへ配信
root注意
clpcfctrl --push -x <構成情報ディレクトリ>
適用中の構成情報を取得
root
clpcfctrl --pull -x /tmp/clpconf
構成情報のチェック(OS設定との整合性)
root
clpcfchk -o /tmp/cfchk -i <構成情報ディレクトリ>

1-4. 初回起動・動作確認

全サーバーでクラスタサービスを起動
root
clpcl -s -a
クラスタ・グループ・リソースの状態を確認
root
clpstat
グループの手動移動(切替試験)
root注意
clpgrp -m <グループ名> -h <移動先サーバー>
クラスタ全体を再起動(起動時の自動起動試験)
root注意
clpstdn -r

1-5. ミラーディスク(Replicator使用時)

ミラー状態を確認
root
clpmdstat --mirror <md名>
ミラーディスクのクラスタパーティション初期化・ファイルシステム作成
root注意
clpmdinit --create quick <md名>
ミラー復帰(初期同期)
root注意
clpmdctrl --recovery <md名>

02構築完了後の構成情報の取得

完成図書(パラメータシート)の裏付けとして取得します。clp.conf は構成全体をXMLで保持しており、差分比較に使えます。

2-1. 構成情報

構成情報(全リソース・モニタの設定値)を詳細表示
root
clpstat -i --detail
クラスタプロパティの設定値
root
clpstat --cl --detail
グループの設定値
root
clpstat --grp <グループ名> --detail
グループリソースの設定値
root
clpstat --rsc <リソース名> --detail
モニタリソースの設定値
root
clpstat --mon <モニタ名> --detail
構成情報ファイル(clp.conf)一式を取得
root
clpcfctrl --pull -x /tmp/clpconf

2-2. ライセンス・バージョン・サービス

ライセンス一覧
root
clplcnsc -l -a
インストールバージョン
rpm -qi clusterpro
CLUSTERPRO関連サービスの自動起動設定
systemctl list-unit-files 'clusterpro*'
CLUSTERPROプロセスの待ち受けポート
root
ss -tulnp | grep clp
タイムアウト倍率の現在値
root
clptoratio -s

03性能情報の取得

CLUSTERPRO自体の負荷は小さいため、主にモニタリソースの監視遅延とOSリソースを確認します。監視タイムアウトが迫っていないかが重要な観点です。

3-1. 監視遅延・稼働状況

モニタリソースの状態と監視間隔・タイムアウト
root
clpstat --mon --detail
モニタ遅延警告(監視処理がタイムアウトに近づいた記録)を抽出
root
grep -i "delay" /opt/nec/clusterpro/log/*.log*
ハートビート経路ごとの状態
root
clpstat --hb

3-2. OSリソース

CPU・メモリ・ハートビートNICの負荷
pkg: sysstat
sar -u -r -n DEV 1 10
共有ディスク・ミラーディスクのI/O負荷(ディスク監視遅延の確認)
pkg: sysstat
iostat -xz 1 10
CLUSTERPROプロセスのリソース使用量
pkg: sysstat
pidstat -u -r -C clp 1 5

04障害時の調査

まず clpstat で異常箇所を特定し、アラートログ・モジュールログで原因を追います。切替が発生した場合は、両ノードのログを同じ時刻範囲で採取してください。

4-1. 状態確認

異常(Error / Offline / Caution)のグループ・リソース・モニタを特定
root
clpstat
自ノードの情報のみ表示(他ノードと通信できないとき)
root
clpstat --local
ハートビート断(ネットワーク分断)の有無
root
clpstat --hb
CLUSTERPRO関連サービスの稼働状態
root
systemctl status 'clusterpro*'

4-2. ログ確認・採取

全ノードのログを一括採取(問い合わせ時に必須)
root
clplogcc -t type1 -o /tmp/clplog
自ノードのみログ採取(他ノードと通信できないとき)
root
clplogcc -l -o /tmp/clplog
モジュールログ(rc.log.cur 等)の更新状況
root
ls -lt /opt/nec/clusterpro/log/
グループ・リソースの起動停止ログ
root
less /opt/nec/clusterpro/log/rc.log.cur
モニタリソースのログ
root
less /opt/nec/clusterpro/log/rm.log.cur
syslogに出力されたCLUSTERPROのアラート
root
grep -i clusterpro /var/log/messages

4-3. 復旧操作

グループを起動
root注意
clpgrp -s <グループ名> -h <サーバー名>
グループを停止
root注意
clpgrp -t <グループ名>
グループリソースを個別起動
root注意
clprsc -s <リソース名>
グループリソースを個別停止
root注意
clprsc -t <リソース名>
モニタの回復動作回数カウンタをリセット
root
clpmonctrl -c -m <モニタ名>
ミラー復帰
root注意
clpmdctrl --recovery <md名>
クラスタサービスを全ノードで再起動
root注意
clpcl -r -a

4-4. 監視の一時停止・タイムアウト調整(調査・暫定対処)

モニタリソースを一時停止(誤検知による切替を防止)
root注意
clpmonctrl -s -m <モニタ名>
モニタリソースを再開
root
clpmonctrl -r -m <モニタ名>
2時間だけタイムアウトを3倍に延長(高負荷処理時の誤検知回避)
root注意
clptoratio -r 3 -t 2h
タイムアウト倍率を元に戻す
root
clptoratio -i

05計画停止・メンテナンス

OSパッチ適用やハードウェア保守時に使う、計画停止の手順です。

5-1. 停止・起動

業務グループを待機系へ移動してから保守を開始
root注意
clpgrp -m <グループ名>
指定サーバーのクラスタサービスのみ停止(片系保守)
root注意
clpcl -t -h <サーバー名>
クラスタをサスペンド(業務を止めずに構成変更を反映)
root注意
clpcl --suspend
クラスタをリジューム
root
clpcl --resume
自サーバーのクラスタサービスを止めて再起動
root注意
clpdown -r
クラスタ全体をシャットダウン
root注意
clpstdn

5-2. 運用中のメッセージ出力

作業開始などをアラートログに記録(作業証跡)
root
clplogcmd -m "メンテナンス開始" --alert

A構成情報一括取得スクリプト

クラスタの構成情報と状態を取得し、ノード単位で保存するスクリプト例です。構築完了時と変更作業の前後で取得し、clp.conf を diff で比較すると構成変更の差分確認に使えます。

一括取得スクリプト（例）
bash
#!/bin/bash
# CLUSTERPRO X 構成情報一括取得スクリプト(root で実行)
OUT=/var/tmp/clp_evidence_$(hostname -s)_$(date +%Y%m%d_%H%M%S)
mkdir -p "$OUT/conf"
run() { echo "### $2" > "$OUT/$1.txt"; eval "$2" >> "$OUT/$1.txt" 2>&1; }
run status    "clpstat"
run config    "clpstat -i --detail"
run heartbeat "clpstat --hb"
run license   "clplcnsc -l -a"
run toratio   "clptoratio -s"
run version   "rpm -qi clusterpro"
run services  "systemctl list-unit-files 'clusterpro*'"
clpcfctrl --pull -x "$OUT/conf" > "$OUT/cfctrl.log" 2>&1
tar czf "$OUT.tar.gz" -C "$(dirname "$OUT")" "$(basename "$OUT")"
echo "出力: $OUT.tar.gz"

B利用上の注意

  • <> で囲んだ値は、環境に合わせて置き換えてください。
  • 「注意」が付いたコマンドは、サービス停止・業務影響・データ変更を伴う可能性があります。本番環境では事前に検証環境で確認し、作業手順書に基づいて実施してください。
  • CLUSTERPRO のコマンドは root で実行します。既定のインストール先は /opt/nec/clusterpro です。
  • 構成の作成・変更は Cluster WebUI で行い、clpcfctrl --push で反映するのが基本です。変更内容によってはサスペンドやクラスタ停止が必要になるため、反映時のメッセージを確認してください。
  • 障害の問い合わせ時は、切替が発生した時刻を含めて全ノードのログを clplogcc で採取してください。
  • ミラーディスク関連(clpmd*)のコマンドは CLUSTERPRO X Replicator を使う構成でのみ使えます。

掲載コマンドは一般的な仕様に基づくサンプルです。バージョンやエディションにより利用できない構文があります。本番環境で実行する前に、検証環境とNECの公式マニュアルで確認してください。
